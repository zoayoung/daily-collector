# 02: 增量预算轮转

**What to build:** 历史增量兜底预算从每轮 100 次提高到 150 次，待兜底候选不再单纯按累计 star 排队，而是按通道交替取号（区间通道一条、新仓库通道一条），直到预算耗尽。效果是低 star 的新项目也能算出数据归属日新增 star，并凭涨幅正常进入入榜集。本地差分命中者依旧不消耗预算，单次历史查询失败的记录方式不变。入榜排序、50 条上限与全零退化规则保持不变，不设通道保底名额。

**Blocked by:** 01: 新仓库通道进候选集

**Status:** done

- [x] 历史增量兜底预算上限提高到每轮 150 次
- [x] 待兜底候选按通道交替取号，两路都能获得预算份额
- [x] 本地差分命中的候选不占用兜底预算
- [x] 单次历史查询失败仍写入注释并把该条记空，行为不变
- [x] 入榜仍按数据归属日新增 star 降序取前 50，不设通道保底名额
- [x] 预算耗尽或候选增量为空时，注释说明原因
- [x] 测试通过采集 CLI 与产物验证：两路候选都拿到增量、入榜顺序正确、预算不超上限

**Acceptance evidence:** 回放两路候选且只有新通道项目有正增量，跑一次采集，产物中该项目出现在入榜集首位；查询次数不超过 150 次。

## Comments

**2026-10-30 · 实现（提交 f546220，合并 25292e1；审查修复 d4bd9bc / 51f51fd）**

- `MAX_HISTORY_CALLS` 100 → 150；待兜底候选先在各通道内按 `stars_total` 降序排队，再按 `CHANNELS` 顺序交替出队，取空一路后继续取另一路。
- 本地差分命中者不进入待兜底队列，不占预算；单次 `stargazers/history` 失败仍记 `gaps` 并把该条记 null。
- 预算耗尽文案区分「未尝试」与「失败」两类数字（审查修复后为「历史增量预算耗尽（上限 150 次），另有 N 个候选未尝试计算增量」）。
- 入榜仍按数据归属日新增 star 降序取前 50，全零退化为累计 star 降序，不设通道保底名额。
- 测试（`tests/test_history_budget.py`）：轮转顺序 `Band/High → New/High → Band/Mid → New/Low`；200 条高 star 区间候选 + 低 star 新项目时后者居首；回放 160/170 条只发出 150 次 history 请求；10 条本地差分 + 150 条待兜底仍发出 150 次；单条失败记 null 并入 `gaps`；`test_failed_history_calls_are_not_counted_as_untried` 覆盖失败与未尝试不混淆。
- 验收：回放两路候选且仅新通道项目有正增量，产物中该项目位列首位，history 调用不超过 150 次。
