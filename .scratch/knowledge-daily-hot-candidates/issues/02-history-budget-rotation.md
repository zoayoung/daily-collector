# 02: 增量预算轮转

**What to build:** 历史增量兜底预算从每轮 100 次提高到 150 次，待兜底候选不再单纯按累计 star 排队，而是按通道交替取号（区间通道一条、新仓库通道一条），直到预算耗尽。效果是低 star 的新项目也能算出数据归属日新增 star，并凭涨幅正常进入入榜集。本地差分命中者依旧不消耗预算，单次历史查询失败的记录方式不变。入榜排序、50 条上限与全零退化规则保持不变，不设通道保底名额。

**Blocked by:** 01: 新仓库通道进候选集

**Status:** ready-for-agent

- [ ] 历史增量兜底预算上限提高到每轮 150 次
- [ ] 待兜底候选按通道交替取号，两路都能获得预算份额
- [ ] 本地差分命中的候选不占用兜底预算
- [ ] 单次历史查询失败仍写入注释并把该条记空，行为不变
- [ ] 入榜仍按数据归属日新增 star 降序取前 50，不设通道保底名额
- [ ] 预算耗尽或候选增量为空时，注释说明原因
- [ ] 测试通过采集 CLI 与产物验证：两路候选都拿到增量、入榜顺序正确、预算不超上限

**Acceptance evidence:** 回放两路候选且只有新通道项目有正增量，跑一次采集，产物中该项目出现在入榜集首位；查询次数不超过 150 次。
