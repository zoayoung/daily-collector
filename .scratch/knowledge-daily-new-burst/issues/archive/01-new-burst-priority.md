# 01: 新爆款优先端到端

**What to build:** 日报先展示“今天刚冒头”的项目，再展示老项目。采集阶段在现有两条候选通道之外，新增一条「近 7 天新建」通道（数据归属日前 7 天创建、累计 star ≥100，按 star 降序，最多 2 页，首页不足 100 条不再翻页），三路候选按 `full_name` 大小写不敏感合并去重。新爆款由 `created_at` 与 `stars_total` 推导，不写布尔字段；采集入榜、分析顺序、整理 `rank` 与渲染统一采用分层排序——新爆款恒在前，层内按数据归属日新增 star 降序，全零时层内退化为累计 star 降序。校验脚本拒绝任何“老项目排在新爆款之前”或层内非降序的产物，并对「发布日 - 8 天」这一跨本地/CI 的边界日期接受任一分层。通道统计扩为三键（区间、新仓库、近 7 天新建），新产物写全三键且三键之和等于候选总数，旧的两键产物仍通过校验。日报中每条新爆款的标题带 `🆕` 标记，概览不新增分组，评分不因新近度加分。工作流 spec、词汇表（新增「新爆款」）、入口指针与整理技能的排序口径同步更新。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 「近 7 天新建」通道按「数据归属日前 7 天创建 + 累计 star ≥100」发起搜索，`per_page=100`、最多 2 页，首页不足 100 条不再翻页
- [x] 三路候选按 `full_name` 大小写不敏感去重，保留首次出现的原始大小写；通道归属只用于统计，不决定分层
- [x] 新爆款判定仅由现有字段推导（创建日期在数据归属日前 7 天内且累计 star ≥100），产物不新增 `is_new` 一类字段
- [x] 分层排序在采集入榜、分析顺序、整理 `rank`、渲染顺序上口径一致：新爆款优先，层内按增量降序；全零时层内按累计 star 降序
- [x] 校验脚本拒绝老项目早于新爆款、以及层内非降序的采集/分析/整理产物
- [x] 校验脚本对「创建日期恰为发布日前 8 天」的条目接受任一分层，本地与 CI 日期口径都能通过
- [x] 通道统计为三键且存在键之和等于候选总数；旧的两键通道统计产物仍通过校验
- [x] 日报中新爆款标题为「名次 + `🆕` + 全名」，非新爆款无标记；概览仍不超过 6 组；评分维度不变
- [x] `gaps` 记录近 7 天新建通道的候选数与失败原因，并说明刷星未做自动判定
- [x] 工作流 spec、词汇表（新增「新爆款」并澄清「采集」与“采集技能”）、入口指针、整理技能排序口径同步更新
- [x] 测试通过采集与校验 CLI 验证：第三通道查询条件与翻页、三路去重、分层顺序、边界容错、三键计数自洽、旧两键兼容

**Acceptance evidence:** 用回放服务器准备三路响应，跑一次采集，产物中近 7 天新建的高增量项目排在所有老项目之前；把某条老项目手动前移或用两键通道统计的旧产物校验，均被拒绝/兼容符合预期；端到端渲染检查 `🆕` 标记只出现在新爆款上。
