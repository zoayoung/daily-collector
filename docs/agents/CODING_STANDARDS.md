# 编码规范

本仓的判断类规范，供 `/code-review` 的「标准轴」审查时阅读。这里只放**判断类**规范——无法用工具机械判定、只能靠审查判断的跨文件一致性；机械类（格式、语法）交给工具，不在此列。

## 单一来源

每份口径只写一处，改行为只改一处。

- 产品口径——数据契约、字段、取值枚举、数值常量、域名与查询串——以 `.scratch/knowledge-daily/spec.md` 为唯一来源。
- `.agents/skills/` 与 `.opencode/agent/` 承载流程与指针：需要产品口径时写「见 spec『X』节」，不复述其内容。

判据（审查用）：若某个数字 / 枚举 / 域名 / 字段清单同时出现在 spec 与某技能或 agent 中，即报 `[判断]` 违反。

机械线索（可选，手动跑）：下面这条命令列出技能/agent 里疑似复述 spec 口径的行（不新增脚本文件，兼容「零脚本」约束）。它是**线索清单，不是门禁**——命中行逐条对照 spec 判断：只有 spec 已定义的口径（数值/枚举/字段清单）才算复述，操作必需者（如按算法写 `stars_today_source=star_history`）不算。

```sh
git grep -n -E '≤ ?[0-9]|15[–-]20|[0-9]+ ?(个?汉字|次/|天|词|条)|字段齐全' -- .agents/skills .opencode/agent
```

## 为什么

口径复述会漂移：改一处漏改另一处，规范与产出互相矛盾。本仓曾因此同时出现多组 spec 与技能不一致的缺陷。
