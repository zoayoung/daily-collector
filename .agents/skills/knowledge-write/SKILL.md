# 知识输出技能（输出阶段）

## 使用场景

主代理委派输出阶段时加载：当日 `analyze.json` 已存在而 `output/YYYY-MM-DD.md` 尚未产出，或用户已确认「仅重写日报 / 覆盖重写」。你只做组装、润色与成文；不重新筛选、不新增条目、不抓取网页。

## 输入

- 委派消息中的日期与产物路径。
- `work/YYYY-MM-DD/analyze.json`（必需；缺失或不可解析时立即失败）。
- 只读：spec（产出与数据契约节）、`AGENTS.md`。

## 执行步骤

1. **读取**：读 analyze.json 与 spec 产出节。完成标志：`github` 条数与 `rank` 顺序、`overview`、主题标签已掌握。
2. **组装概览**：写 `## 今日概览`——先一句总述（取自 `overview.lead`），再按 `overview.themes` 逐主题一条 bullet：`- **[主题]**：要点一句`；0 命中主题不出现。完成标志：概览为分点结构。
3. **组装趋势列表**：写 `## GitHub 趋势`，按 `rank` 排序，每条：标题（`### N. full_name`）+ 主题行（`- 主题：[AI / LLM]`，多枚并列如 `[AI / LLM] [Golang]`，空则 `[其他]`；`repeat` 条目在主题行后带 `🔁 重复：上次 YYYY-MM-DD`，30 天内突破的附新进展）+ 链接 + 核心内容 + 为什么值得关注。完成标志：每条四要素齐全、主题标签与标记照抄分析产物。
4. **润色成文**：条目按「标题 + 链接 + 核心内容 + 为什么值得关注」润色，保留分析段的评价、理由与建议；**核心内容压缩到 ≤100 个汉字**（不计英文单词与数字），不改事实数据。
5. **自检落盘**：对照「输出契约」自检，覆盖写入 `output/YYYY-MM-DD.md`；按模板回复。

## 输出契约

产物 `output/YYYY-MM-DD.md`（UTF-8，中文；项目名/标题保留原文）。写文件前自检：

- 结构完整：日期标题、今日概览、GitHub 趋势齐全；概览为「一句总述 + 主题分点」；
- 无独立主题节；主题只以标签形式出现在趋势条目上；
- GitHub 15–20 条、顺序与 `rank` 一致、主题标签与 `repeat` 标记照抄分析产物；
- 每条标题、链接、核心内容（≤100 汉字）、为什么值得关注齐全；
- 事实数据（star、日期、链接等）照抄，不改写、不编造。

最终回复：

- 成功：`✅ 输出完成；产物：output/YYYY-MM-DD.md；GitHub N 条；概览主题 T 个`
- 失败：`❌ 输出失败；原因：…；已落盘：无；建议：…`

## 失败模式

- analyze.json 缺失或不可解析：立即失败，不自行分析或抓取。
- 个别字段缺失：用已有信息合理补全（不改变事实数据）；完全无法成文才失败。
- 写入失败：按失败模板返回。
- 同日文件已存在：直接覆盖（覆盖确认由主代理在委派前完成）。

## 正反向自测

- 正向：按输出契约自检清单逐项核对并确认结构完整后，才算完成。
- 反向：前置缺失或组装不出完整结构时，不写半成品文件，并按失败模板返回。

## 权限边界

- 允许：读 `AGENTS.md`、spec、`work/`、`output/`；写仅 `output/**`；TodoWrite。
- 硬边界：不写 `work/` 与历史日报、不增删条目或改顺序、事实数据照抄、不抓取网页、不询问用户。
